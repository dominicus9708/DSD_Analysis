# DSD Analysis Purpose Taxonomy

DSD Analysis uses **purpose** and **external domain** as separate classification axes.

## A. Falsification and contradiction search

Primary question: can a legal DSD model, extension, or integrated layer be forced into contradiction or supplied with a countermodel to a stated axiom/theorem?

Typical outputs:
- direct countermodel attempt
- consistency obstruction
- integration conflict
- distinction between an internal contradiction and an external design limitation

Primary existing cases: 008, 009, 010.

## B. Coherence and consistency comparison

Primary question: are the DSD distinctions jointly interpretable and compatible with independently developed formal disciplines under explicit assumptions?

Typical outputs:
- direct compatibility
- conditional compatibility
- weaker/stronger comparison
- non-correspondence without contradiction
- identification of what is inherited from standard mathematics versus added by DSD

Primary existing cases: 001, 002, 003, 005, 006, 007.

Next prepared case: `COH-001` / global case `011`.

## C. Describability and predefinition justification

Primary question: has a definition, sort, function type, existence assumption, observer condition, or promotion rule already excluded alternatives before the intended analysis begins?

Typical outputs:
- hidden promotion rule
- signature/type exclusion
- unjustified existential or applicability import
- observer/describability prerequisite
- result change after weakening or removing the predefinition

Primary existing cases: 004 and the pre-axiom typing finding in 008.

## D. Structural reinterpretation and application

Primary question: does separating formation, applicability, relation, value, and composition clarify an external problem without merely renaming the source theory?

Typical outputs:
- problem decomposition
- ambiguity removal
- responsibility/decision structure clarification
- software/data semantics clarification
- philosophical thought-experiment audit

## Classification rule

Every case receives:

- one **primary purpose**;
- zero or more secondary purpose tags;
- one external domain path under `cases/`;
- a mapping judgment: `direct / partial / after encoding / no mapping`;
- a separate answer to whether DSD actually contributes to solving or clarifying the source problem.

A failure to map is not automatically a falsification. A successful mapping is not automatically evidence that the DSD axioms are true.
